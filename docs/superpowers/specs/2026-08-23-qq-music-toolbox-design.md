# QQ 音乐格式转换工具箱设计

日期：2026-08-23

## 1. 目标

在“咕咕嘎嘎的个人博客”中重新加入工具箱，并提供一个与主页视觉系统一致的 QQ 音乐格式转换页面。转换实现直接采用用户提供的 `hook_qq_music.js` 所使用的 Frida 方法，不依赖或引用现有 Ventriloc 项目。

用户体验目标：

1. 用户先启动 QQ 音乐。
2. 用户双击博客项目附带的本地桥接程序。
3. 用户打开博客工具箱，选择 `.mflac` 或 `.mgg` 文件。
4. 页面显示排队、解密和完成状态，并提供结果下载。

桥接程序负责自动加载 Python/Frida 运行环境。用户不需要手动执行 Python 命令、安装 Python 包或运行 `run.bat`。

## 2. 必要运行边界

用户提供的 hook 使用 Frida 提供的 `Module`、`NativeFunction`、`Memory`、`File` 和 `rpc.exports`。它会查找 `QQMusicCommon.dll` 中的 `EncAndDesMediaFile` 导出符号，并在 `QQMusic.exe` 进程内调用这些原生函数。

因此以下条件不能删除：

- Windows 系统已安装 QQ 音乐；
- 转换时 `QQMusic.exe` 正在运行；
- QQ 音乐进程已加载兼容版本的 `QQMusicCommon.dll`；
- 本地桥接程序与 QQ 音乐进程的架构兼容。

Netlify 只托管静态博客页面，不执行解密，不保存上传文件，也不承载 Python 或 Frida。

## 3. 架构

系统分成两个相互隔离的单元。

### 3.1 博客工具箱

博客增加两个路由：

- `/tools`：工具箱索引；
- `/tools/qq-music-converter`：格式转换页面。

页面职责：

- 选择或拖入文件；
- 校验扩展名；
- 将文件发送到 `http://127.0.0.1:8765`；
- 轮询任务状态；
- 显示进度、错误和下载入口；
- 检测桥接程序是否在线；
- 桥接离线时给出明确的启动或下载说明。

页面不包含 Frida 代码，也不尝试直接访问系统进程。

### 3.2 独立本地桥接程序

博客仓库中新建 `bridge/qq-music/`，它是一个独立、可测试、可打包的本地组件，不导入 Ventriloc 仓库中的任何代码。

桥接程序包含：

- 用户提供的 `hook_qq_music.js`；
- Python HTTP 服务；
- Frida 调用适配器；
- 串行任务队列；
- 临时文件和结果文件管理；
- PyInstaller 打包配置；
- 一键构建和运行脚本。

最终产物是 Windows 可执行程序 `qq-music-bridge.exe`。启动后它只监听 `127.0.0.1:8765`，自动打开或提示博客工具页面；关闭程序后本地接口停止。

## 4. 数据流

```text
选择 .mflac / .mgg
        ↓
博客页面校验文件名、扩展名和大小
        ↓
POST http://127.0.0.1:8765/api/convert
        ↓
桥接程序保存到每个任务独立的临时目录
        ↓
串行工作线程连接 QQMusic.exe
        ↓
加载 hook_qq_music.js 并调用 rpc.exports.decrypt
        ↓
QQMusicCommon.dll 读取解密后的媒体字节
        ↓
生成 .flac / .ogg
        ↓
页面轮询任务并下载结果
        ↓
桥接程序清理上传的加密源文件
```

转换映射固定为：

| 输入 | 输出 |
| --- | --- |
| `.mflac` | `.flac` |
| `.mgg` | `.ogg` |

## 5. 本地 API

### `GET /api/health`

返回桥接程序版本、服务状态和 QQ 音乐进程检测结果。

### `POST /api/convert`

请求体为二进制文件，文件名通过 ASCII 安全编码后的 `X-File-Name` 传递。成功后返回任务 ID。

### `GET /api/jobs/{jobId}`

返回 `queued`、`processing`、`completed` 或 `failed`，以及进度、阶段和用户可读错误。

### `GET /api/download/{jobId}`

仅允许下载已完成任务产生的文件。

原生转换调用必须串行执行，避免多个任务同时操作 QQ 音乐的原生解密对象。

## 6. 安全与隐私

- 服务只绑定 `127.0.0.1`，不监听局域网或公网地址；
- CORS 只允许 `https://gugugaga-blog.netlify.app` 和明确列出的本地开发地址；
- 支持 Private Network Access 预检；
- 只接受 `.mflac` 和 `.mgg`；
- 使用安全 basename，拒绝目录穿越；
- 单个文件最大 1 GB；
- 每个任务使用独立临时目录；
- 转换结束或失败后删除上传的加密副本；
- 下载路径必须位于桥接程序的输出目录内；
- 不记录音频内容，不把文件发送到互联网。

该功能定位为处理用户有权访问和备份的个人音频文件。

## 7. 页面与视觉设计

工具箱继续使用博客现有设计变量和组件，不建立第二套品牌系统。

- 背景使用 Obsidian/Abyss 深色表面；
- 标题使用主页的 `Noto Serif SC` 展示字体；
- 正文使用 Inter，状态和格式标签使用 Roboto Mono；
- 主色使用 Iris、Periwinkle 和 Cyan；
- 导航复用现有玻璃胶囊样式；
- 卡片复用细边框、圆角和 `border-trace` 动效；
- 页面进入和滚动动效遵循现有 `prefers-reduced-motion` 规则；
- 桌面端采用转换面板加说明侧栏；
- 移动端改为单列，文件名允许省略显示，页面不得横向溢出。

转换页包括：

1. 标题、支持格式与隐私说明；
2. 桥接状态和 QQ 音乐状态；
3. 拖拽/文件选择区域；
4. 文件队列、进度、错误和下载按钮；
5. 首次使用说明与桥接程序下载入口。

桥接在线时隐藏冗长的首次使用步骤，只保留状态摘要。

## 8. 错误处理

| 场景 | 页面提示 |
| --- | --- |
| 桥接程序未启动 | 显示“本地桥接未连接”和启动/下载入口 |
| QQ 音乐未运行 | 显示“请先启动 QQ 音乐” |
| Frida 无法连接进程 | 显示桥接错误，建议以当前用户身份重启 QQ 音乐和桥接程序 |
| DLL 或导出符号变化 | 显示“当前 QQ 音乐版本暂不兼容” |
| 不支持的文件 | 在上传前拒绝并说明支持格式 |
| 文件为空或过大 | 在浏览器和桥接程序两层拒绝 |
| 转换失败 | 保留任务错误，允许用户移除或重试 |
| 浏览器阻止本地网络请求 | 显示浏览器权限说明，不回退到远程上传 |

用户错误不得暴露 Python 堆栈、系统路径或内部异常细节。

## 10. 发布方式

- 博客继续通过 GitHub `main` 分支触发 Netlify 部署；
- 桥接程序源码与博客代码放在同一仓库，但作为独立目录构建；
- Windows 可执行文件发布到博客仓库的 GitHub Releases，不提交进 Git 历史；
- 工具页面的下载按钮指向固定的最新 Release 地址；
- 第一阶段只发布 Windows x64 版本；
- QQ 音乐升级导致符号失效时，通过新的桥接版本修复，不要求修改博客页面接口。

## 11. 非目标

- 不把现有 Ventriloc 项目合并到博客；
- 不从 Ventriloc 仓库复制 Python 服务实现；
- 不提供云端上传和远程转换；
- 不把 Frida hook 直接放入浏览器执行；
- 不捆绑或重新分发 QQ 音乐；
- 不在第一阶段支持 macOS、Linux 或移动端本地转换；
- 不实现与格式转换无关的音频编辑、转码或标签管理。

## 12. 验收标准

1. 首页导航可以进入工具箱，工具箱可以进入格式转换页。
2. 工具页面在视觉、字体、颜色、卡片和动效上与主页一致。
3. 未启动桥接时页面可用，并清楚说明如何启动或下载。
4. 启动桥接且 QQ 音乐运行后，页面能完成文件提交、进度显示和结果下载。
5. `.mflac` 输出 `.flac`，`.mgg` 输出 `.ogg`，原文件不被修改。
6. 文件不发送到公网，桥接程序只监听本机回环地址。
7. 两个现有项目保持独立，博客不引用 Ventriloc 仓库。
8. 博客生产构建、前端测试和桥接自动化测试全部通过。
9. Windows x64 桥接程序可以通过 GitHub Release 下载并独立启动。
